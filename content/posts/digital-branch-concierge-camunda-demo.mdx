## Coming soon

The Camunda build is in progress. It builds the same concierge as the n8n and LangGraph demos, against the same demo customers, knowledge and twelve test conversations, so the three can be compared on the same terms.

Camunda is the build where the boundary is drawn on the diagram. The outer process is BPMN, so the fixed paths are literally fixed, and the agent lives inside an ad-hoc sub-process that acts as its toolbox. If the article's diagram looks like a process model to you, this is the build that makes it one.

## What the build will show

<TickList>

<TickItem>

**The process as a BPMN model**: identification, the concierge conversation, the impact and policy gate as an exclusive gateway, a user task for the named decision owner and the outcome.

</TickItem>

<TickItem>

**The agent inside an ad-hoc sub-process**, using Camunda's AI Agent connector, with the skills modelled as the only tasks it may activate.

</TickItem>

<TickItem>

**Every human decision as a user task**, so the automated decision-making line is visible in the model before anything runs.

</TickItem>

<TickItem>

**Lineage in Operate**: every tool the agent chose, every gateway decision and every point where the process took the decision back.

</TickItem>

</TickList>
